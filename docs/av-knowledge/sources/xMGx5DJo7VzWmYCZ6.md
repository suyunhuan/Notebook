自动驾驶规控模块，都有哪些关键的方法论提升端到端表现的性能，比如 dpo、grpo、改真值、配比、loss、动态 weight、reward 等技巧都是怎么做的
自动驾驶规控（Planning & Control）端到端：性能提升方法论汇总
背景：传统规控是感知→预测→规划→控制模块化流水线；端到端规控一般指从原始输入（图像 / 点云 / BEV 特征）直接输出轨迹、速度、方向盘 / 油门指令，中间不拆显式预测、占用栅格。
你提到的 DPO、GRPO、真值改造、样本配比、Loss 设计、动态权重、Reward 函数，在智驾端到端里和大模型有相似思想，但约束完全不一样：智驾有硬安全约束、时序连续性、物理可执行性、交通规则，不能像 LLM 只追求文本合理性。
整体分为 6 大块：
真值（Label）改造策略
样本配比 / 数据采样策略
Loss 函数 & 动态权重设计
Reward 建模（强化学习 RL 基础）
偏好对齐类：DPO / IPO 等（替代传统 RLHF）
策略梯度类：GRPO、PPO 在线优化
一、真值改造（改真值，最基础、收益稳定）
端到端规控的真值不是简单抄人类司机轨迹，人类驾驶本身有噪声、滞后、危险操作、个体风格差异，直接学 raw human 轨迹会学坏。常见改造手段：
1. 轨迹平滑与物理约束过滤
对采集的人类轨迹做二阶 / 三阶平滑（加 jerk 加加速度约束），剔除突变急刹、抖方向盘的异常片段；
用车辆动力学模型（单车模型 / IPG/Carsim）做可行性校验：真值轨迹必须满足车辆动力学可达，不满足就修正或丢弃；
核心目的：不要让模型学习物理不可实现的轨迹。
2. 多候选真值（不是单一条最优轨迹）
人类同一个场景可以有多种合法驾驶方案（比如跟车可以近一点 / 远一点）。
标注多条可行轨迹，标注偏好等级：安全优先 > 舒适优先 > 激进；
训练时，只要模型输出落在可行轨迹集合内就视为正确，而不是强制拟合某一条单一轨迹；
这是 DPO 在智驾里落地的前提：需要成对偏好样本（better/worse）。
3. 真值修正：修复人类错误
人类在危险场景会出现失误：离障碍物过近、压线、抢道。这类样本不能当作正真值；
方案：用专家规控器（传统优化规划器，比如 QP 规划）重新生成安全参考轨迹替换人类坏真值；
混合真值：简单场景用人类轨迹，危险 / Corner Case 用专家规划器生成真值。
4. 时序对齐、时间戳补偿
司机操作有延迟，传感器和司机动作不同步；需要做时间校准，把真值轨迹对齐到模型输入帧的时间戳。
5. 负样本真值构造
人为构造危险轨迹（碰撞、压线、侵入邻道），作为不希望模型输出的目标，用于偏好学习、对比学习。
二、样本配比 & 采样策略
智驾天然数据长尾：95% 都是正常直行，事故 / 鬼探头 / 无保护左转这类 Corner Case 极少。直接随机采样会导致模型只会开 “顺风局”。
1. 加权重采样（Loss 权重只是一部分，采样在前）
按场景稀有度加权：Corner Case 高采样权重，普通场景降权重；
分层采样：固定每 batch 里，普通场景、变道、路口、障碍物、危险场景维持固定比例；
注意：不能过度放大少数危险样本，否则模型容易过度保守、频繁急刹。
2. Hard Example Mining（难例挖掘）
离线：在数据集上跑旧模型，找出模型预测误差大、安全违规高的样本，提升它们的采样概率；
在线：训练过程中，每轮评估，筛选违反安全约束的样本，放回训练集。
3. 域配比：多场景分布对齐
高速、城区、环岛、雨天、夜间，控制分布；仿真数据和实车数据配比（仿真用来补长尾，实车保证域 gap）。
4. 拒绝有害样本
过滤：司机分心、误踩、碰撞事故样本；这类样本不能直接当监督信号，要么丢弃，要么转为负偏好样本。
关键点：采样配比是前置，动态 Loss weight 是后置，两者配合，不要混淆。

② 基于模型误差的动态权重（难例自适应）
对每个样本：模型预测误差越大，自动放大该样本总 loss 权重；

风险：单纯放大难例会导致模型震荡，一般搭配梯度裁剪。
③ 权重退火策略
训练前期：高权重给轨迹拟合 Loss，让模型先学会基础开车；
训练后期：逐步提升安全、舒适性正则权重，做精细化对齐。
坑点：多目标 Loss 之间冲突。例如：贴近跟车符合人类轨迹，但安全代价高。固定权重很难平衡，这也是为什么大家转向偏好学习（DPO）而不是单纯调 loss 权重。

Reward 设计两个主流范式：
稠密 Reward：每一帧都计算，适合短时序规划；缺点：奖励函数设计偏见很大，模型会 hack reward（例如停车拿安全奖励）。
稀疏 Reward：只有发生碰撞 / 到达终点才给奖励，学习难度高，一般配合辅助稠密奖励。
智驾端到端 RL 几乎都在仿真环境训练；实车 RL 风险太高，无法在线探索危险动作。
Reward 权重调优技巧
奖励归一化：不同量纲项做归一化，防止某一项 Reward 主导；
惩罚项用hinge 代价：只有违反阈值之后才开始惩罚，正常区间不影响；
举例：距离障碍物 > 1m，安全惩罚 = 0；小于 1m，惩罚随距离下降快速上升。
五、DPO（Direct Preference Optimization，偏好对齐，现在智驾端到端很热）
原理一句话
DPO不需要训练单独的 Reward 网络，也不需要 PPO 的在线采样；直接用成对偏好样本（同一个场景下两条轨迹：chosen更好，rejected更差），优化策略，提升好轨迹相对坏轨迹的概率。
在 LLM 里 DPO 替代 RLHF；在智驾规控：DPO 用来对齐驾驶偏好、安全、舒适，解决多目标冲突问题，可以叠加在监督预训练（SFT）之后。
智驾 DPO 怎么做
构造成对样本（关键）
同一个场景，两条候选轨迹：
chosen：安全、舒适、符合人类偏好（专家 / 优质司机轨迹）
rejected：危险、抖动、压线、保守 / 激进坏轨迹（人工构造或者旧模型输出）
来源：人类标注成对偏好、专家规划器生成好坏轨迹、仿真里生成对比轨迹。
DPO loss 公式（智驾一般适配连续动作 / 轨迹输出版本）
标准 DPO 针对离散 token；规控是连续轨迹输出，常用：连续 DPO / IPO / KL-DPO，约束新策略和旧策略之间 KL 散度，防止策略崩坏。
训练流程
Step1：SFT 监督预训练，用大量轨迹真值，让模型学会基础生成可行轨迹；
Step2：DPO 偏好微调，用偏好对，让模型优先输出安全舒适轨迹，而不是死板拟合人类所有行为；
DPO 的优势 & 局限
✅ 优势：相比 PPO，不需要仿真环境在线 rollout，训练稳定；不需要 reward model；可以直接在离线数据集上做偏好对齐；解决 “拟合人类错误” 的痛点。
❌ 局限：依赖高质量成对偏好样本；不能自动发现训练集外的全新危险 case；对未见过场景泛化有限。
变体 IPO（Implicit Preference Optimization），KL 约束更稳定，智驾端到端也有使用。
六、GRPO（Group Relative Policy Optimization，组相对策略优化）
GRPO 是 DeepSeek 提出，最初用于大模型推理奖励，属于 PPO 家族的改进，免单独 Reward Model；最近迁移到机器人、智驾端到端规控。
GRPO 核心思想
对同一个输入场景，策略网络采样多条候选轨迹（一组 group），然后基于 Reward 函数给组内多条轨迹打分排序；用组内相对排名来更新策略，而不是绝对 Reward。
GRPO 在规控落地步骤
输入场景 BEV / 图像特征，策略网络采样 N 条候选轨迹；
用 Reward 函数（安全、舒适、规则）对组内 N 条轨迹打分；
在 group 内部做相对归一化 Reward，减去组均值；
策略梯度更新：提升组内高分轨迹概率，压低低分轨迹概率；
不需要单独训练 Reward Model，Reward 可以直接是人工写的代价函数。
GRPO vs PPO vs DPO

智驾里 GRPO 典型用法：在仿真环境，对同一个场景，让端到端规控模型输出多条候选轨迹，用安全 reward 打分，做组内排序优化，提升模型生成安全最优轨迹的能力。
缺点：需要对每个场景多次前向生成多条轨迹，训练算力开销更大；依赖 Reward 函数质量，Reward 设计有坑，模型依然会 hack。
完整训练链路（行业主流组合方案）
plaintext
原始数据 → 真值清洗&修正 → 重采样配比（普通+难例）
→ SFT监督训练（多目标Loss+动态权重）
→ 【可选】DPO离线偏好微调（用好/坏轨迹对对齐安全偏好）
→ 【可选】仿真环境GRPO/PPO在线优化，进一步提升长尾场景性能
→ 评估：仿真+实车，安全违规率、舒适性、接管率

关键权衡总结（工程踩坑点）
SFT 打底是基础：DPO/GRPO 不是万能，没有 SFT 基础，策略会直接崩坏；
DPO 适合离线偏好对齐，改善驾驶风格、剔除人类坏行为；GRPO 适合仿真空间内轨迹搜索优化，挖掘更好的候选轨迹；两者不是替代关系，可以串联；
动态 Loss 权重是静态监督学习时代的手段，很难解决多目标冲突；偏好学习（DPO）本质把 “权重调参” 转化为偏好样本定义；
RL/GRPO 几乎只能在仿真做；实车不能用在线探索，会出安全事故；
所有方法都绕不开：长尾场景、分布偏移、安全约束硬边界。端到端规控现在工业界一般依然保留安全校验层（兜底规则 / 优化器），模型输出轨迹之后做安全过滤。

一、智驾端到端规控 DPO：负样本（rejected 轨迹）构造全方法

chosen：优选轨迹（安全、合规、舒适）

负样本不是随便拿别的场景危险片段，核心约束：场景 s 固定，只有轨迹不同。
下面按工程落地成本从低到高排序，同时说明各自优缺点。
1. 同场景旧模型输出作为 rejected（最常用）
做法
拿已经训练好的 SFT 模型（SFT checkpoint）在数据集 / 仿真里推理，对同一场景生成多条候选轨迹：
选一条高质量的作为 chosen（可以是专家真值 / SFT 最优输出）
把模型其他较差输出（压线、跟车过近、抖动、保守龟速）标记为 rejected
细分两种：
采样多条轨迹（加 dropout、温度采样），同模型多轨迹，好的 chosen，差的 rejected；
用更早版本的模型输出当 rejected（模型迭代自举：新版本作为 chosen，旧版本作为 rejected）。
✅ 优点：自动批量生成，不需要大量人工标注；分布贴近模型本身错误，精准修正模型弱点。
❌ 缺点：rejected 缺陷类型有限，只能覆盖模型当前会犯的错；很难生成分布外极端危险 case。
2. 专家规划器生成 rejected（QP / 优化规划器，工业首选）
做法
同一场景，调用传统优化规划器（QP 规划器）：
正常参数：生成安全舒适轨迹 → chosen
修改规划器代价函数 / 约束，人为制造缺陷轨迹 → rejected
降低障碍物代价：生成离障碍物很近的轨迹
降低平滑代价：生成大 jerk 抖动轨迹
放宽车道约束：生成压线轨迹
调高时间代价：生成极度保守、停车等待的轨迹
✅ 优点：可控，可以精准控制 rejected 违反哪一类约束；真值一致性强，不存在人类司机噪声；可以批量构造 corner case 偏好对。
❌ 缺点：依赖传统规划器，复杂路口场景，规划器本身可能失效；生成的坏轨迹和真实人类错误分布有 gap。
3. 人类轨迹拆分：同司机同场景的多行为片段
做法
同一连续驾驶场景，人类司机本身会有多种操作：
好片段：平稳跟车、安全变道 → chosen
同场景下司机短暂失误片段：跟车偏近、小幅压线、急刹 → rejected
⚠️ 重点：不能拿碰撞严重事故片段做 rejected，这类场景本身状态分布偏移，容易污染 DPO 训练。
✅ 优点：偏好对来自真实世界，偏好符合人类驾驶员真实感受。
❌ 缺点：真实场景里同一个场景出现好坏轨迹对天然很少，需要大量人工筛选标注；人类失误样本少，长尾 case 不足。
4. 扰动真值轨迹（离线合成 rejected，低成本扩充）
做法
以原始优质 chosen 轨迹为基准，对轨迹点做可控扰动：
空间扰动：x/y 方向偏移，往障碍物 / 车道边界偏移；
时序扰动：修改速度 / 加速度，制造急加减速；
平滑度扰动：增加高频抖动，拉高 jerk。
控制扰动幅度：不要直接生成物理不可行轨迹，否则 DPO 会学到无效对比。
✅ 优点：数据量无限扩充，成本极低；可以按类别批量生成不同类型缺陷负样本。
❌ 缺点：纯数学扰动，很多坏轨迹在真实驾驶里不会出现；分布容易脱离真实世界，过度使用会导致 DPO 过拟合人造扰动。
5. 仿真环境 rollout 生成偏好对（长尾 case 专用）
做法
在仿真器里固定场景（鬼探头、无保护左转、环岛交汇）：
策略 rollout 多条轨迹；
规则 reward 打分排序；高分 chosen，低分 rejected。
✅ 优点：专门补真实数据稀缺的 corner case；可以构造极端危险负样本。
❌ 缺点：仿真域 gap；成本高；依赖仿真场景库。
6. 人工标注偏好对（高质量小样本，用来校准）
做法
标注员看同一场景下两条轨迹，只做偏好判断：哪条开得更好，不需要标注轨迹坐标。
一般不大量用，只做少量黄金样本，用来校验前面自动生成偏好对的质量，防止自动生成的偏好对存在偏好歧义。
二、负样本的分类 & 避坑要点
DPO rejected 轨迹分两大类，训练效果差异很大：
弱负样本（推荐为主）：同场景两条都物理可行，只是风格 / 安全 / 舒适有优劣。
例如：跟车距离 1.2m（chosen）vs 0.7m（rejected，没碰撞但是偏危险）。DPO 主要靠这类样本学习偏好。
强负样本（少量使用）：轨迹直接违反硬约束（碰撞、压线）。
强负样本不要太多！大量强负会让模型直接变成极度保守，遇到任何物体就急刹。
❌ 绝对禁止：跨场景构造偏好对！比如 A 场景好轨迹和 B 场景坏轨迹配对，DPO 完全失效。
三、DPO 训练数据配比，以及和 SFT 阶段的关系
前置总原则
SFT 是底座，DPO 是偏好微调；DPO 不能从零训练，必须基于 SFT 预训练权重。
SFT 学习：如何生成可行轨迹（分布、动力学、基础交通规则）；
DPO 学习：在可行轨迹集合里，优先选择更好的那条，抑制坏轨迹。
1. SFT 阶段的数据构成
SFT 数据集以单条真值轨迹样本为主，不是轨迹对。
典型配比参考（工程经验）：
常规场景：70%（高速、城市正常直行跟车）
普通交互场景：20%（变道、路口正常通行）
难例 / 长尾：10%（鬼探头、无保护左转等）
SFT 阶段，不要混入大量危险真值；SFT 真值优先选人类 / 专家的安全可行轨迹。
SFT 目标：模型输出轨迹分布落在可行域；如果 SFT 学出来轨迹本身物理不可行，DPO 完全救不回来。
SFT 训练完成之后，评估指标重点看：轨迹可行性、碰撞率、车道保持。只要基础可行，再进入 DPO。

① 场景分布配比（推荐）

② 弱负 vs 强负偏好对配比（核心调参点）
推荐：弱负样本占 80%，强负样本占 20% 以内。
弱负：轨迹可行，只是偏危险 / 不舒服（主力，用来学习驾驶偏好）
强负：碰撞、压线等硬违规轨迹（少量，用来建立安全底线）
坑：强负 > 30%，模型大概率过度保守，出现无故急刹、不敢通过路口。
③ 不同负样本来源的混合配比（参考）
DPO 数据集可以混合多种方式生成的偏好对：
旧模型输出偏好对：50%（修正模型原生错误）
专家规划器生成偏好对：30%（可控安全边界）
仿真 rollout 偏好对：15%（补长尾）
人工标注黄金偏好对：5%（校准偏好，防止偏好漂移）
3. SFT 和 DPO 的数据关联 & 样本复用策略
方案 A：复用 SFT 数据集场景生成 DPO 偏好对（最常用）
SFT 用的原始场景，直接拿来构造 DPO 轨迹对：
chosen：SFT 阶段使用的真值轨迹
rejected：扰动真值 / SFT 模型推理坏轨迹
✅ 优点：场景分布一致，域 gap 最小；不需要额外采集大量新场景。
注意：同一个场景不要同时在 SFT batch 和 DPO batch 混合训练；一般两阶段串行：SFT 训练完成，冻结底座或者低学习率做 DPO 微调。
方案 B：新增独立场景集做 DPO 偏好对
单独采集 / 仿真一批场景，只用于 DPO，不参与 SFT。适合专门提升长尾场景。
风险：场景分布和 SFT 差异大 → 微调后常规场景性能掉点。
方案 C：SFT+DPO 混合训练（不推荐，风险高）
把 SFT 单轨迹样本 + DPO 轨迹对放在同一个训练轮次联合训练。
容易出现：多目标冲突，模型在拟合真值和偏好之间来回震荡；只有少数团队在做探索，工业主流是串行。
4. DPO 训练时，batch 内的配比细节
DPO 一个 batch 里面全部是轨迹对，不再混入 SFT 单真值样本（串行方案）；
batch 内部依然分层采样：维持常规 / 交互 / 难例的比例；
对难例偏好对，可以加样本权重：难例对 loss 权重上浮 1.5~3 倍，但不要过高。
5. 训练配比相关超参联动
当你提高强负样本比例：DPO 的 beta（DPO 温度系数）建议调低；beta 越小，对好坏轨迹差异惩罚越强；强负多的时候 beta 太大会导致策略崩坏。
弱负为主时：beta 可以取偏大值，偏好学习更平滑。
beta 是 DPO 最重要超参之一，智驾连续轨迹 DPO 一般 beta 在 0.1~1 区间，远小于 LLM。
四、迭代链路总结（SFT → DPO）
SFT 数据集：单条安全真值轨迹，场景分布常规为主 + 少量难例；训练得到基础规控模型，保证轨迹物理可行。
在 SFT 场景池 + 仿真场景池，批量构造 DPO 偏好对：
chosen：专家 / 优质真值；
rejected：旧模型输出、扰动轨迹、改参规划器轨迹；控制弱负为主，强负少量。
DPO 数据集场景分布：大体对齐 SFT，适度提升难例偏好对占比。
DPO 微调：低学习率，KL 约束，防止大幅度偏离 SFT 底座分布。
评估：同时看常规场景性能、长尾场景安全指标、保守度（急刹率）。
五、常见失败案例（来自工程）
rejected 全部是强负轨迹 → 模型极度保守，接管率飙升；
偏好对跨场景构建 → DPO 完全学不到偏好，指标无提升；
DPO 场景和 SFT 分布差异巨大 → 微调后基础驾驶能力退化；
只用扰动真值生成 rejected，缺少真实模型错误样本 → 仿真指标涨，实车不涨。

比如怎么生成碰撞、换道负样本、速度缩放等样本呢，有哪些规则方法
核心前提
所有下面生成的 (s, τ_chosen, τ_rejected) 必须同一个场景 s（同一帧 BEV / 图像、障碍物状态、车道完全不变），只修改轨迹；
τ_chosen：安全合规、动力学可行的基准轨迹（专家规划器 / 清洗后的人类真值 / SFT 优质输出）
τ_rejected：在同一场景下生成坏轨迹，分为三类：碰撞负样本、换道违规负样本、速度缩放负样本
生成后都要做两步校验：
动力学校验：轨迹的加速度、jerk、前轮转角在车辆物理极限内；不要生成物理不可达轨迹（DPO 会学到无效对比）
偏好校验：不能出现 “好坏搞反”；自动打分过滤歧义样本（两条轨迹分数接近就丢弃该偏好对）
一、碰撞类 rejected 轨迹生成（强负样本，控制占比≤20%）
目标：同一场景，轨迹侵入障碍物占用空间，但分两种：硬碰撞（会撞上）、近距侵入（不碰撞但安全余量不足，弱负）
建议：碰撞负样本里，70% 是近距侵入弱负，30% 真实碰撞硬负，避免模型过度保守。
方法 1：横向偏移基准轨迹（最常用）
输入：基准轨迹 τ_chosen = [(x₀,y₀,v₀), (x₁,y₁,v₁)...(x_T,y_T,v_T)]
规则：
沿着轨迹每个点的法向（垂直于前进方向）做横向偏移；
偏移方向：朝向障碍物（行人、车辆、护栏）；
偏移量按距离障碍物远近自适应：
障碍物距离 > 2m：偏移 0.6~1.2m（近距侵入，弱负）
障碍物距离 < 2m：偏移 1.2~2.0m（直接侵入障碍物 bbox，硬碰撞，强负）
平滑：偏移后对整条轨迹做 3 阶多项式平滑，保证a/jerk不超限。
例子：前方有停止车辆，基准轨迹保持 1.5m 横向余量；横向向障碍物偏移 0.9m → 横向余量只剩 0.6m（近距侵入 rejected）；偏移 1.5m → 轨迹直接压进车辆 bbox（碰撞 rejected）。
方法 2：纵向时间偏移（追尾类负样本）
适合前车跟车场景：
保持轨迹横向坐标不变；
把未来轨迹点在时间轴上往前压缩：让自车更早到达同一空间位置，等效自车速度变快；
公式思路：
基准轨迹：t=2s 到达 x=20m；
坏轨迹：t=1.2s 到达 x=20m；
结果：自车更快追上前车，TTC（碰撞时间）下降，甚至 TTC<0 触发追尾。
注意：要限制加速度上限，不能瞬间加速。
方法 3：修改规划器代价函数生成碰撞轨迹（工业首选，可控）
复用 QP 规划器（同一场景，障碍物 / 车道不变）：
基准：障碍物代价权重w_obs=10 → chosen 轨迹
生成 rejected：降低障碍物代价 w_obs=0.1~2，保持车道、平滑代价不变；规划器会生成贴近障碍物甚至侵入障碍物占用区域的轨迹。
优点：天然满足动力学约束，不需要后续额外平滑；可以批量控制碰撞类型（横向碰撞 / 追尾）。
碰撞负样本过滤规则（必加）
计算轨迹上每个时刻的距离障碍物最小距离 d_min；
若 d_min > 1.0m：不算碰撞负，丢弃；
若 d_min < 0：硬碰撞（保留少量）；
若 0 < d_min <1.0m：近距侵入弱负（主力碰撞类负样本）；
额外：TTC 阈值过滤，TTC<1.5s 标记为危险轨迹。
二、换道 / 变道违规负样本（车道越界、不合理换道，弱负为主）
分两类：① 车道压线 / 越界；② 时机错误换道（邻道有车，强行变道）
类型 A：压线 / 跨车道边界负样本
方法 A1：横向偏移基准轨迹（车道方向）
基准轨迹保持在车道中心（chosen）；
沿法向朝车道线方向偏移，偏移量：0.3~1.2m；
偏移 0.4m：轮胎压车道线（弱负）
偏移 1.0m：整车侵入邻车道（强负）
保持纵向速度不变，轨迹平滑，保证动力学可行。
方法 A2：修改 QP 车道代价权重
同一场景：
chosen：车道边界代价w_lane=8，不压线；
rejected：w_lane=0.5~2，障碍物代价不变；规划器会生成压线 / 侵入邻道轨迹。
类型 B：时机错误的强行换道负样本（交互场景，价值很高）
场景：邻道后方有来车，正常应当放弃变道；
生成规则
基准 chosen：放弃变道，留在原车道；
rejected：强制规划器输出变道轨迹，但邻道后方车辆的 TTC 很小；
实现方式：强制关闭 “邻道来车安全约束”，保留车道平滑代价；规划器输出一条几何上可行变道轨迹，但邻道车辆距离过近。
重点：这条 rejected 轨迹几何和动力学是可行的，只是交互上不安全，属于高质量弱负，DPO 最擅长学习这类偏好。
换道负样本过滤规则
计算轨迹与车道边界的最小距离；
区分：仅压线 / 完全侵入邻车道；
强行变道样本必须校验邻道车辆 TTC：TTC<2.5s 才标记为坏变道；TTC 很大的变道是合理的，不能作为 rejected；
剔除：跨实线掉头、逆行这类极端轨迹（少量保留，强负）。

五、自动打分规则：给轨迹打分，自动构建 chosen/rejected 配对
生成多条候选轨迹后，用一套 rule-based reward 自动排序，用来配对，不需要人工：
plaintext
score = 0
# 安全项
score - = max(0, 1.0 - min_d_obs) * 5.0  # 离障碍物小于1m开始扣分
score - = max(0, 0.5 - min_d_lane) * 3.0 # 压线扣分
score - = (TTC < 2.5) * 4.0              # TTC过小扣分
# 舒适项
score - = max(0, abs(jerk) - 2.0) * 0.8
score - = max(0, abs(a) - 3.0) * 0.8
# 效率项
score -= max(0, v_ref - v)*0.3 # 速度过低扣分

同一 s 场景下多条候选轨迹：
score 最高 → chosen
score 次高 / 中等偏低 → rejected（优先选这种，弱负）
score 极低 → 强负（少量采样）
过滤歧义样本：两条轨迹分数差小于阈值（比如 < 0.5），直接丢弃该组，好坏不明确，会污染 DPO。
六、配比、训练注意事项
负样本类型配比（DPO 数据集内所有偏好对）
速度 / 舒适性负样本：~40%（弱负主力，学习平稳驾驶）
换道 / 车道违规负样本：~40%（交互场景偏好）
碰撞侵入类负样本：~20%（其中 30% 硬碰撞，70% 近距弱负）
和 SFT 关系：
SFT 阶段只用安全可行轨迹，不会用这些扰动坏轨迹当真值；
DPO 是在 SFT 学会可行轨迹分布之后，用这组偏好对，学习 “多条可行轨迹里怎么选更好的一条”。
坑点：
不要生成物理不可行轨迹；模型会学到无意义对比；
不要一条 rejected 叠加多重缺陷；信号模糊；
强负（碰撞）比例不能太高，否则模型保守；
扰动幅度不要过大，人造痕迹太重，实车泛化差。
七、可选扩展：负样本增强的高级策略
自适应扰动幅度：根据 SFT 模型当前误差，模型容易犯错的场景，扰动幅度调小一点，生成更贴近模型错误边界的 rejected；
困难偏好对挖掘：SFT 模型在该场景预测误差大，优先在这类场景生成 DPO 偏好对；
域混合：一部分扰动生成、一部分 QP 改代价生成、一部分旧模型输出混合，避免单一来源负样本带来的分布偏移。

一、真值构造完整流水线（工业标准）
Step1：原始轨迹提取
从回放 log 里提取自车历史 + 未来轨迹：
自车定位 / IMU 输出的历史位姿序列；
把司机未来一段时间（比如未来 3s/5s，10Hz）的位姿插值，得到原始 raw 轨迹；
问题：司机操作有系统延迟 + 反应滞后 + 噪声。传感器、标定、时间不同步会造成时间戳错位。
Step2：时序对齐（必做）
传感器、定位、司机油门 / 转角信号存在时间偏移（几十～200ms）；
用时间戳补偿，把司机动作对齐到 BEV / 图像输入帧的时刻；
例子：图像帧在 t=0，司机打方向实际发生在 t=+0.15s，要回拨对齐，否则真值时序错位，模型学不准。
Step3：基础清洗过滤（过滤直接丢弃，不进真值库）
直接扔掉这类原始司机片段，不做修复，不拿来当 gt：
司机分心、低头、误操作、急打方向、无意识猛踩刹车；
采集异常：定位漂移、丢帧、点云 / 图像失效；
事故、碰撞、剐蹭片段（这类样本不做 SFT 真值，可以留着后续做 DPO 负样本）；
车辆处于接管、停机、标定模式。

原始司机轨迹有抖动、高频转角噪声：
空间平滑：多项式拟合 / 样条 / 最小 jerk 优化，平滑 x/y 轨迹；
求导得到速度、加速度、jerk；

Step5：真值修正 / 替换（重点，下面详细讲哪些场景要改）
分两类操作：

全局替换：完全抛弃司机轨迹，用专家规划器（QP / 优化规划）重新生成参考轨迹作为 gt。
Step6：多真值标注（多候选可行轨迹，为 DPO 铺垫）
同一个场景可以存在多条合理驾驶策略：
跟车：远跟 / 近跟；
变道：早变 / 晚变；
对同一个场景标注多条可行、安全的真值轨迹，标记不同驾驶风格（保守 / 中性 / 激进）。SFT 可以选中性作为主 gt；其余候选轨迹后面用于 DPO 偏好对。
Step7：真值质量打分入库
打分维度：安全余量、是否压线、TTC、jerk、轨迹可行性；低于阈值不入库。
二、哪些场景必须修改 / 替换原始司机真值（重点）
原则：司机行为不符合安全 / 交通规则，或者不是最优示范，就要修正。
分成 5 大类场景：
1. 司机出现轻微不安全操作（局部修正，优先，不整体废掉整条轨迹）
特点：整体驾驶没问题，只是局部小瑕疵，不构成碰撞，但安全余量不足。
跟车距离偏近，TTC 偏低，但没有碰撞；
车辆轻微压车道线（轮胎压线，没有跨道）；
近距离紧贴护栏 / 非机动车行驶；
过弯横向余量偏小；
✅ 处理方案：局部微调轨迹
保持整体路线不变，只把轨迹往安全侧小幅偏移：拉大跟车距离、离开车道线、远离障碍物；再做平滑 + 动力学校验。
不要直接整条删掉：场景本身很宝贵（城区交互），只是司机小动作有瑕疵。
2. 司机做出明显违规、危险行为（整条轨迹替换，不用司机轨迹）
原始司机轨迹直接不能当 SFT 真值：
实线变道；
无保护左转抢行，对向有来车；
路口抢黄灯、超速通过；
近距离切入大货车；
高速近距离连续变道；
✅ 处理方案：抛弃司机轨迹，调用专家优化规划器，在完全相同的场景（障碍物、车道、交通灯不变）重新生成一条合规安全参考轨迹作为真值。
场景保留，只是真值换掉。这类场景大多是高价值 corner case，直接丢弃太浪费。
3. 司机保守过度（龟速，通行效率过低）
场景本身通行条件很好，但司机过度保守：
空旷路口，无障碍物，长时间低速蠕行；
高速无车，长期远低于限速行驶；
有条件安全变道，但司机一直不做合理变道，长时间压慢车流。
✅ 处理方案：替换速度剖面，保持空间轨迹不变，提升速度到合理区间；动力学校验。
原因：直接学这个真值，模型会学出过度保守，通行效率差，后续接管率高。
4. 交互场景：司机滞后 / 反应延迟（非常常见，城区重点）
典型：前方车辆减速，司机刹车踩晚了，出现紧急制动；
或者前车加速离开后，司机迟迟不恢复正常车速。
司机轨迹本身没碰撞，但属于 “补救式急刹”，不是预判式的优质驾驶。
✅ 处理方案：
保留空间路线，修正时序 / 速度曲线，提前减速，消除突发急刹，降低 jerk；
让真值变成预判型减速，而不是临危一脚刹车。
这个修正是城区真值改造最高收益的一项。原始司机很多都是滞后反应，直接学就会模型急刹多。
5. 采集 / 定位带来的轨迹失真（不是司机驾驶问题，是数据问题）
定位漂移，轨迹局部 “蛇形抖动”；
时间戳错位，导致速度剖面畸变；
弯道定位偏差，看起来压线实际没有压线。
✅ 处理：轨迹拟合平滑、时间对齐、基于车道几何修正轨迹中心线。
6. 仿真数据真值（天然需要构造，没有人类司机）
仿真场景（鬼探头、横穿行人、无保护左转）：
不存在人类回放轨迹，直接用专家规划器生成真值。
可以批量生成中性风格的参考轨迹，作为 SFT 真值。
❌ 哪些场景不要强行修改真值（保留原样）
正常合理的驾驶风格差异：有的司机习惯远跟，有的中性跟车，只要安全合规，不修改，可以作为多真值；
合理的防御性减速：路口、行人附近主动减速，这是好行为，不要改成更快速度；
临时避让合理操作：遇到突发障碍物平稳避让，轨迹安全，保留。
一句话区分：
司机行为安全、合规、预判合理 → 保留，只做基础平滑对齐；
司机行为余量不足、违规、滞后补救、极端保守 / 激进 → 局部修正 or 整条替换。
三、真值修改的两种技术实现方案
方案 A：局部轨迹优化（微调，保留司机路线）
以原始司机 xy 轨迹作为初始猜测，加约束做优化：
目标函数：贴近原始司机轨迹 + 最小 jerk
约束：
障碍物距离 > 安全阈值（比如 0.8~1m）
车道边界约束，不压线
加速度、jerk、转向角物理边界
适合：轻微瑕疵场景，尽量保留人类驾驶意图，只修复局部缺陷。
方案 B：全量专家规划重生成（完全替换 gt）
固定场景的 BEV 静态 / 动态障碍物、车道、红绿灯，运行 QP / 非线性优化规划器，重新求解最优轨迹，完全不用司机轨迹。
适合：司机行为明显危险 / 违规、抢行、急刹补救这类 corner case。
四、真值构造和 SFT / DPO 之间的联动（很关键）
SFT 真值一定是安全、可行、优质轨迹，不允许危险轨迹进入 SFT 真值库；危险司机轨迹不做 gt，但可以提取场景，拿来构造 DPO rejected 负样本；
多真值：同场景多条可行安全轨迹，都可以作为 SFT 备选 gt；同时直接拿来组成 DPO 的 chosen/rejected 偏好对；
真值改造不要过度：如果大量真值都是专家重写的，脱离人类真实行为分布，SFT 模型会 “不像人开车”，实车域 gap 变大；
工程配比经验：
常规场景：80% 清洗平滑后的原始司机轨迹（少量局部微调）
城区交互 /corner case：20% 专家规划重生成的替换真值
五、踩坑清单
真值修改后，只看几何不校验动力学：生成的轨迹 a/jerk 超限，模型学不可行轨迹；
过度修正：把合理的司机防御减速抹平，真值变成激进轨迹；
场景状态不同步：替换真值的时候，忘记同步当时障碍物 / 红绿灯状态，真值和场景不匹配（致命错误）；
统一一套安全阈值处理所有场景：高速安全余量阈值和城区路口不能用同一个参数；
全部依赖专家规划生成真值，几乎不用人类轨迹，模型行为和真实人类驾驶偏差大，实车泛化差。

三、转向回正场景（过弯结束回方向盘、直线小扰动回正）
注意：端到端规控有两种输出范式：
A：输出轨迹 (x,y,v)（无显式转角）；
B：直接输出方向盘转角 / 前轮转角序列。
回正问题在 B 范式更突出；A 范式下回正间接体现在轨迹曲率时序：出弯后曲率平滑收敛到 0，不能曲率保持、不能来回振荡。
现象
出弯后，模型不回正 / 回正滞后 / 回正超调（S 摆动）。
根源：原始司机回正动作差异极大；很多人出弯回正时机不稳定，轨迹曲率衰减时序混乱。
1）真值改造方法
如果输出是轨迹（曲率时序版，绝大多数 BEV 规划）
原始轨迹：出弯后曲率缓慢下降、或者来回震荡。
修正思路：固定空间路径，约束曲率随弧长平滑衰减到 0
入弯：曲率逐步上升到峰值；
弯顶：维持恒定曲率；
出弯段：曲率平滑单调衰减到 0，禁止曲率二次反向（S 摆动）；
用样条拟合，增加曲率变化率约束 
dκ/ds
，禁止曲率振荡。
如果输出是转角序列（直接控制）
需要对前轮转角 δ 时序做真值修正：
入弯：δ 平滑增加；
弯内：δ 保持；
出弯：随曲率减小，单调平滑回正到 0，转角变化率受限；
人类经常出现：弯结束还保留转角、回正太快导致反向摆，这类片段需要替换转角真值。
关键点：回正不是 “出弯瞬间立刻归零”，而是随行驶距离逐步回正，和车辆动力学（阿克曼、轮胎侧偏）匹配，不能脱离车辆动力学硬改转角时序。
2）回正场景数据增强
同一弯道场景，生成多条曲率时序：
中性（主 gt）：标准平滑单调曲率衰减；
略快回正；
略慢回正（仍然稳定，无振荡）；
全部作为可行多真值，用于 SFT。

回正超调：曲率从正→负，轨迹 S 摆动；
回正动作突变，转角变化率过大。

# 初始化状态
def reset():
    a_lon_ema = 0.0
    a_lat_ema = 0.0
    j_lon_ema = 0.0
    j_lat_ema = 0.0
    return a_lon_ema, a_lat_ema, j_lon_ema, j_lat_ema

alpha = 0.181 # tau=0.5s, dt=0.1
# 舒适阈值
soft_a_lon = 1.5
hard_a_lon = 2.5
k_a_lon = 0.3

def hinge_quad(x, x_soft, x_hard, k):
    absx = abs(x)
    if absx <= x_soft:
        return 0.0
    elif absx <= x_hard:
        return k * (absx - x_soft)**2
    else:
        base = k * (x_hard - x_soft)**2
        return base + 0.5 * (absx - x_hard)

# 每一步更新
def step(a_lon_raw, a_lat_raw, j_lon_raw, j_lat_raw, state):
    a_lon_ema, a_lat_ema, j_lon_ema, j_lat_ema = state
    # EMA时间衰减平滑
    a_lon_ema = alpha * a_lon_raw + (1-alpha)*a_lon_ema
    a_lat_ema = alpha * a_lat_raw + (1-alpha)*a_lat_ema
    j_lon_ema = alpha * j_lon_raw + (1-alpha)*j_lon_ema

    # 查表获得各分项代价
    c_alon = hinge_quad(a_lon_ema, soft_a_lon, hard_a_lon, k_a_lon)
    c_alat = hinge_quad(a_lat_ema, 1.2, 2.0, 0.35)
    c_jlon = hinge_quad(j_lon_ema, 1.5, 2.5, 0.5)
    c_jlat = hinge_quad(j_lat_ema, 2.0, 3.0, 0.4)

    w_alon, w_alat, w_jlon, w_jlat = 0.2,0.25,0.4,0.3
    total_cost = w_alon*c_alon + w_alat*c_alat + w_jlon*c_jlon + w_jlat*c_jlat
    r_comfort = -total_cost
    new_state = (a_lon_ema, a_lat_ema, j_lon_ema, j_lat_ema)
    return r_comfort, new_state, total_cost

python
import numpy as np

# ========= 超参 =========
dt = 0.1
tau_smooth = 0.3    # 信号平滑时间常数
tau_decay = 0.5     # cost的时间衰减常数
alpha = 1 - np.exp(-dt / tau_smooth)

# 分项权重
w_alon, w_alat, w_jlon, w_jlat = 0.2, 0.25, 0.4, 0.3

# 四段代价函数
def cost_alon(x):
    x_soft, x_hard, k1, k2 = 1.5, 2.5, 0.3, 0.8
    absx = abs(x)
    if absx <= x_soft:
        return 0.0
    elif absx <= x_hard:
        return k1 * (absx - x_soft)**2
    else:
        base = k1 * (x_hard - x_soft)**2
        return base + k2 * (absx - x_hard)

def cost_alat(x):
    x_soft, x_hard, k1, k2 = 1.2, 2.0, 0.35, 0.9
    absx = abs(x)
    if absx <= x_soft:
        return 0.0
    elif absx <= x_hard:
        return k1 * (absx - x_soft)**2
    else:
        base = k1 * (x_hard - x_soft)**2
        return base + k2 * (absx - x_hard)

def cost_jlon(x):
    x_soft, x_hard, k1, k2 = 1.5, 2.5, 0.5, 1.2
    absx = abs(x)
    if absx <= x_soft:
        return 0.0
    elif absx <= x_hard:
        return k1 * (absx - x_soft)**2
    else:
        base = k1 * (x_hard - x_soft)**2
        return base + k2 * (absx - x_hard)

def cost_jlat(x):
    x_soft, x_hard, k1, k2 = 2.0, 3.0, 0.4, 1.0
    absx = abs(x)
    if absx <= x_soft:
        return 0.0
    elif absx <= x_hard:
        return k1 * (absx - x_soft)**2
    else:
        base = k1 * (x_hard - x_soft)**2
        return base + k2 * (absx - x_hard)

def calc_total_comfort_cost(traj):
    """
    traj: array(N,4) [a_lon, a_lat, j_lon, j_lat]
    return: total comfort cost
    """
    N = traj.shape[0]
    # 初始化EMA状态
    a_lon_filt = 0.0
    a_lat_filt = 0.0
    j_lon_filt = 0.0
    j_lat_filt = 0.0
    total_cost = 0.0
    for i in range(N):
        alon_raw, alat_raw, jlon_raw, jlat_raw = traj[i]
        # Step1 EMA平滑acc/jerk
        a_lon_filt = alpha * alon_raw + (1-alpha)*a_lon_filt
        a_lat_filt = alpha * alat_raw + (1-alpha)*a_lat_filt
        j_lon_filt = alpha * jlon_raw + (1-alpha)*j_lon_filt
        j_lat_filt = alpha * jlat_raw + (1-alpha)*j_lat_filt

        # Step2 查表获得单点分项cost
        c_alon = cost_alon(a_lon_filt)
        c_alat = cost_alat(a_lat_filt)
        c_jlon = cost_jlon(j_lon_filt)
        c_jlat = cost_jlat(j_lat_filt)
        ci = w_alon*c_alon + w_alat*c_alat + w_jlon*c_jlon + w_jlat*c_jlat

        # Step3 时间衰减权重
        tau_i = i * dt
        lam = np.exp(-tau_i / tau_decay)
        total_cost += ci * lam
    return total_cost

自动驾驶规控（Planning & Control）端到端：性能提升方法论汇总
背景：传统规控是感知→预测→规划→控制模块化流水线；端到端规控一般指从原始输入（图像 / 点云 / BEV 特征）直接输出轨迹、速度、方向盘 / 油门指令，中间不拆显式预测、占用栅格。
你提到的 DPO、GRPO、真值改造、样本配比、Loss 设计、动态权重、Reward 函数，在智驾端到端里和大模型有相似思想，但约束完全不一样：智驾有硬安全约束、时序连续性、物理可执行性、交通规则，不能像 LLM 只追求文本合理性。
整体分为 6 大块：
真值（Label）改造策略
样本配比 / 数据采样策略
Loss 函数 & 动态权重设计
Reward 建模（强化学习 RL 基础）
偏好对齐类：DPO / IPO 等（替代传统 RLHF）
策略梯度类：GRPO、PPO 在线优化
一、真值改造（改真值，最基础、收益稳定）
端到端规控的真值不是简单抄人类司机轨迹，人类驾驶本身有噪声、滞后、危险操作、个体风格差异，直接学 raw human 轨迹会学坏。常见改造手段：
1. 轨迹平滑与物理约束过滤
对采集的人类轨迹做二阶 / 三阶平滑（加 jerk 加加速度约束），剔除突变急刹、抖方向盘的异常片段；
用车辆动力学模型（单车模型 / IPG/Carsim）做可行性校验：真值轨迹必须满足车辆动力学可达，不满足就修正或丢弃；
核心目的：不要让模型学习物理不可实现的轨迹。
2. 多候选真值（不是单一条最优轨迹）
人类同一个场景可以有多种合法驾驶方案（比如跟车可以近一点 / 远一点）。
标注多条可行轨迹，标注偏好等级：安全优先 > 舒适优先 > 激进；
训练时，只要模型输出落在可行轨迹集合内就视为正确，而不是强制拟合某一条单一轨迹；
这是 DPO 在智驾里落地的前提：需要成对偏好样本（better/worse）。
3. 真值修正：修复人类错误
人类在危险场景会出现失误：离障碍物过近、压线、抢道。这类样本不能当作正真值；
方案：用专家规控器（传统优化规划器，比如 QP 规划）重新生成安全参考轨迹替换人类坏真值；
混合真值：简单场景用人类轨迹，危险 / Corner Case 用专家规划器生成真值。
4. 时序对齐、时间戳补偿
司机操作有延迟，传感器和司机动作不同步；需要做时间校准，把真值轨迹对齐到模型输入帧的时间戳。
5. 负样本真值构造
人为构造危险轨迹（碰撞、压线、侵入邻道），作为不希望模型输出的目标，用于偏好学习、对比学习。
二、样本配比 & 采样策略
智驾天然数据长尾：95% 都是正常直行，事故 / 鬼探头 / 无保护左转这类 Corner Case 极少。直接随机采样会导致模型只会开 “顺风局”。
1. 加权重采样（Loss 权重只是一部分，采样在前）
按场景稀有度加权：Corner Case 高采样权重，普通场景降权重；
分层采样：固定每 batch 里，普通场景、变道、路口、障碍物、危险场景维持固定比例；
注意：不能过度放大少数危险样本，否则模型容易过度保守、频繁急刹。
2. Hard Example Mining（难例挖掘）
离线：在数据集上跑旧模型，找出模型预测误差大、安全违规高的样本，提升它们的采样概率；
在线：训练过程中，每轮评估，筛选违反安全约束的样本，放回训练集。
3. 域配比：多场景分布对齐
高速、城区、环岛、雨天、夜间，控制分布；仿真数据和实车数据配比（仿真用来补长尾，实车保证域 gap）。
4. 拒绝有害样本
过滤：司机分心、误踩、碰撞事故样本；这类样本不能直接当监督信号，要么丢弃，要么转为负偏好样本。
关键点：采样配比是前置，动态 Loss weight 是后置，两者配合，不要混淆。

Reward 设计两个主流范式：

稀疏 Reward：只有发生碰撞 / 到达终点才给奖励，学习难度高，一般配合辅助稠密奖励。
智驾端到端 RL 几乎都在仿真环境训练；实车 RL 风险太高，无法在线探索危险动作。

惩罚项用hinge 代价：只有违反阈值之后才开始惩罚，正常区间不影响；
举例：距离障碍物 > 1m，安全惩罚 = 0；小于 1m，惩罚随距离下降快速上升。
五、DPO（Direct Preference Optimization，偏好对齐，现在智驾端到端很热）
原理一句话
DPO不需要训练单独的 Reward 网络，也不需要 PPO 的在线采样；直接用成对偏好样本（同一个场景下两条轨迹：chosen更好，rejected更差），优化策略，提升好轨迹相对坏轨迹的概率。
在 LLM 里 DPO 替代 RLHF；在智驾规控：DPO 用来对齐驾驶偏好、安全、舒适，解决多目标冲突问题，可以叠加在监督预训练（SFT）之后。
智驾 DPO 怎么做
构造成对样本（关键）
同一个场景，两条候选轨迹：
chosen：安全、舒适、符合人类偏好（专家 / 优质司机轨迹）
rejected：危险、抖动、压线、保守 / 激进坏轨迹（人工构造或者旧模型输出）
来源：人类标注成对偏好、专家规划器生成好坏轨迹、仿真里生成对比轨迹。
DPO loss 公式（智驾一般适配连续动作 / 轨迹输出版本）
标准 DPO 针对离散 token；规控是连续轨迹输出，常用：连续 DPO / IPO / KL-DPO，约束新策略和旧策略之间 KL 散度，防止策略崩坏。
训练流程
Step1：SFT 监督预训练，用大量轨迹真值，让模型学会基础生成可行轨迹；
Step2：DPO 偏好微调，用偏好对，让模型优先输出安全舒适轨迹，而不是死板拟合人类所有行为；
DPO 的优势 & 局限
✅ 优势：相比 PPO，不需要仿真环境在线 rollout，训练稳定；不需要 reward model；可以直接在离线数据集上做偏好对齐；解决 “拟合人类错误” 的痛点。
❌ 局限：依赖高质量成对偏好样本；不能自动发现训练集外的全新危险 case；对未见过场景泛化有限。
变体 IPO（Implicit Preference Optimization），KL 约束更稳定，智驾端到端也有使用。
六、GRPO（Group Relative Policy Optimization，组相对策略优化）
GRPO 是 DeepSeek 提出，最初用于大模型推理奖励，属于 PPO 家族的改进，免单独 Reward Model；最近迁移到机器人、智驾端到端规控。
GRPO 核心思想
对同一个输入场景，策略网络采样多条候选轨迹（一组 group），然后基于 Reward 函数给组内多条轨迹打分排序；用组内相对排名来更新策略，而不是绝对 Reward。
GRPO 在规控落地步骤
输入场景 BEV / 图像特征，策略网络采样 N 条候选轨迹；
用 Reward 函数（安全、舒适、规则）对组内 N 条轨迹打分；
在 group 内部做相对归一化 Reward，减去组均值；
策略梯度更新：提升组内高分轨迹概率，压低低分轨迹概率；
不需要单独训练 Reward Model，Reward 可以直接是人工写的代价函数。
GRPO vs PPO vs DPO
表格
方法	数据来源	是否需要仿真 rollout	核心特点	适用场景
PPO	在线交互采样	✅	绝对 Reward，容易 reward hack，训练不稳定	仿真环境，充分交互
GRPO	同场景多候选轨迹采样	✅	组内相对 Reward，不需要 RM，方差更低	仿真生成多条轨迹，搜索最优轨迹
DPO	离线成对偏好样本	❌	离线偏好对，不需要在线 rollout	已有大量标注好坏轨迹，做偏好对齐
智驾里 GRPO 典型用法：在仿真环境，对同一个场景，让端到端规控模型输出多条候选轨迹，用安全 reward 打分，做组内排序优化，提升模型生成安全最优轨迹的能力。
缺点：需要对每个场景多次前向生成多条轨迹，训练算力开销更大；依赖 Reward 函数质量，Reward 设计有坑，模型依然会 hack。
完整训练链路（行业主流组合方案）
plaintext
原始数据 → 真值清洗&修正 → 重采样配比（普通+难例）
→ SFT监督训练（多目标Loss+动态权重）
→ 【可选】DPO离线偏好微调（用好/坏轨迹对对齐安全偏好）
→ 【可选】仿真环境GRPO/PPO在线优化，进一步提升长尾场景性能
→ 评估：仿真+实车，安全违规率、舒适性、接管率

关键权衡总结（工程踩坑点）
SFT 打底是基础：DPO/GRPO 不是万能，没有 SFT 基础，策略会直接崩坏；
DPO 适合离线偏好对齐，改善驾驶风格、剔除人类坏行为；GRPO 适合仿真空间内轨迹搜索优化，挖掘更好的候选轨迹；两者不是替代关系，可以串联；
动态 Loss 权重是静态监督学习时代的手段，很难解决多目标冲突；偏好学习（DPO）本质把 “权重调参” 转化为偏好样本定义；
RL/GRPO 几乎只能在仿真做；实车不能用在线探索，会出安全事故；
所有方法都绕不开：长尾场景、分布偏移、安全约束硬边界。端到端规控现在工业界一般依然保留安全校验层（兜底规则 / 优化器），模型输出轨迹之后做安全过滤。

rejected：劣轨迹（同一帧场景，其他可行 / 不可行轨迹，不能换场景）
负样本不是随便拿别的场景危险片段，核心约束：场景 s 固定，只有轨迹不同。
下面按工程落地成本从低到高排序，同时说明各自优缺点。
1. 同场景旧模型输出作为 rejected（最常用）
做法
拿已经训练好的 SFT 模型（SFT checkpoint）在数据集 / 仿真里推理，对同一场景生成多条候选轨迹：
选一条高质量的作为 chosen（可以是专家真值 / SFT 最优输出）
把模型其他较差输出（压线、跟车过近、抖动、保守龟速）标记为 rejected
细分两种：
采样多条轨迹（加 dropout、温度采样），同模型多轨迹，好的 chosen，差的 rejected；
用更早版本的模型输出当 rejected（模型迭代自举：新版本作为 chosen，旧版本作为 rejected）。
✅ 优点：自动批量生成，不需要大量人工标注；分布贴近模型本身错误，精准修正模型弱点。
❌ 缺点：rejected 缺陷类型有限，只能覆盖模型当前会犯的错；很难生成分布外极端危险 case。
2. 专家规划器生成 rejected（QP / 优化规划器，工业首选）
做法
同一场景，调用传统优化规划器（QP 规划器）：
正常参数：生成安全舒适轨迹 → chosen
修改规划器代价函数 / 约束，人为制造缺陷轨迹 → rejected
降低障碍物代价：生成离障碍物很近的轨迹
降低平滑代价：生成大 jerk 抖动轨迹
放宽车道约束：生成压线轨迹
调高时间代价：生成极度保守、停车等待的轨迹
✅ 优点：可控，可以精准控制 rejected 违反哪一类约束；真值一致性强，不存在人类司机噪声；可以批量构造 corner case 偏好对。
❌ 缺点：依赖传统规划器，复杂路口场景，规划器本身可能失效；生成的坏轨迹和真实人类错误分布有 gap。
3. 人类轨迹拆分：同司机同场景的多行为片段
做法
同一连续驾驶场景，人类司机本身会有多种操作：
好片段：平稳跟车、安全变道 → chosen
同场景下司机短暂失误片段：跟车偏近、小幅压线、急刹 → rejected
⚠️ 重点：不能拿碰撞严重事故片段做 rejected，这类场景本身状态分布偏移，容易污染 DPO 训练。
✅ 优点：偏好对来自真实世界，偏好符合人类驾驶员真实感受。
❌ 缺点：真实场景里同一个场景出现好坏轨迹对天然很少，需要大量人工筛选标注；人类失误样本少，长尾 case 不足。
4. 扰动真值轨迹（离线合成 rejected，低成本扩充）
做法
以原始优质 chosen 轨迹为基准，对轨迹点做可控扰动：
空间扰动：x/y 方向偏移，往障碍物 / 车道边界偏移；
时序扰动：修改速度 / 加速度，制造急加减速；
平滑度扰动：增加高频抖动，拉高 jerk。
控制扰动幅度：不要直接生成物理不可行轨迹，否则 DPO 会学到无效对比。
✅ 优点：数据量无限扩充，成本极低；可以按类别批量生成不同类型缺陷负样本。
❌ 缺点：纯数学扰动，很多坏轨迹在真实驾驶里不会出现；分布容易脱离真实世界，过度使用会导致 DPO 过拟合人造扰动。
5. 仿真环境 rollout 生成偏好对（长尾 case 专用）
做法
在仿真器里固定场景（鬼探头、无保护左转、环岛交汇）：
策略 rollout 多条轨迹；
规则 reward 打分排序；高分 chosen，低分 rejected。
✅ 优点：专门补真实数据稀缺的 corner case；可以构造极端危险负样本。
❌ 缺点：仿真域 gap；成本高；依赖仿真场景库。
6. 人工标注偏好对（高质量小样本，用来校准）
做法
标注员看同一场景下两条轨迹，只做偏好判断：哪条开得更好，不需要标注轨迹坐标。
一般不大量用，只做少量黄金样本，用来校验前面自动生成偏好对的质量，防止自动生成的偏好对存在偏好歧义。
二、负样本的分类 & 避坑要点
DPO rejected 轨迹分两大类，训练效果差异很大：
弱负样本（推荐为主）：同场景两条都物理可行，只是风格 / 安全 / 舒适有优劣。
例如：跟车距离 1.2m（chosen）vs 0.7m（rejected，没碰撞但是偏危险）。DPO 主要靠这类样本学习偏好。
强负样本（少量使用）：轨迹直接违反硬约束（碰撞、压线）。
强负样本不要太多！大量强负会让模型直接变成极度保守，遇到任何物体就急刹。
❌ 绝对禁止：跨场景构造偏好对！比如 A 场景好轨迹和 B 场景坏轨迹配对，DPO 完全失效。
三、DPO 训练数据配比，以及和 SFT 阶段的关系
前置总原则
SFT 是底座，DPO 是偏好微调；DPO 不能从零训练，必须基于 SFT 预训练权重。
SFT 学习：如何生成可行轨迹（分布、动力学、基础交通规则）；
DPO 学习：在可行轨迹集合里，优先选择更好的那条，抑制坏轨迹。
1. SFT 阶段的数据构成
SFT 数据集以单条真值轨迹样本为主，不是轨迹对。
典型配比参考（工程经验）：
常规场景：70%（高速、城市正常直行跟车）
普通交互场景：20%（变道、路口正常通行）
难例 / 长尾：10%（鬼探头、无保护左转等）
SFT 阶段，不要混入大量危险真值；SFT 真值优先选人类 / 专家的安全可行轨迹。
SFT 目标：模型输出轨迹分布落在可行域；如果 SFT 学出来轨迹本身物理不可行，DPO 完全救不回来。
SFT 训练完成之后，评估指标重点看：轨迹可行性、碰撞率、车道保持。只要基础可行，再进入 DPO。

① 场景分布配比（推荐）
整体 DPO 偏好对集合，场景分布建议和 SFT 场景分布保持大体对齐，但提升难例比例：
常规场景偏好对：50%
普通交互场景偏好对：30%
长尾 / 难例偏好对：20%
为什么不能把 DPO 全部换成难例对？
如果 DPO 全是 corner case 偏好对，模型在常规场景的驾驶行为会退化；DPO 微调是在原有 SFT 分布上做偏好修正，不是重训底座。
② 弱负 vs 强负偏好对配比（核心调参点）
推荐：弱负样本占 80%，强负样本占 20% 以内。
弱负：轨迹可行，只是偏危险 / 不舒服（主力，用来学习驾驶偏好）
强负：碰撞、压线等硬违规轨迹（少量，用来建立安全底线）
坑：强负 > 30%，模型大概率过度保守，出现无故急刹、不敢通过路口。
③ 不同负样本来源的混合配比（参考）
DPO 数据集可以混合多种方式生成的偏好对：
旧模型输出偏好对：50%（修正模型原生错误）
专家规划器生成偏好对：30%（可控安全边界）
仿真 rollout 偏好对：15%（补长尾）
人工标注黄金偏好对：5%（校准偏好，防止偏好漂移）
3. SFT 和 DPO 的数据关联 & 样本复用策略
方案 A：复用 SFT 数据集场景生成 DPO 偏好对（最常用）
SFT 用的原始场景，直接拿来构造 DPO 轨迹对：
chosen：SFT 阶段使用的真值轨迹
rejected：扰动真值 / SFT 模型推理坏轨迹
✅ 优点：场景分布一致，域 gap 最小；不需要额外采集大量新场景。
注意：同一个场景不要同时在 SFT batch 和 DPO batch 混合训练；一般两阶段串行：SFT 训练完成，冻结底座或者低学习率做 DPO 微调。
方案 B：新增独立场景集做 DPO 偏好对
单独采集 / 仿真一批场景，只用于 DPO，不参与 SFT。适合专门提升长尾场景。
风险：场景分布和 SFT 差异大 → 微调后常规场景性能掉点。
方案 C：SFT+DPO 混合训练（不推荐，风险高）
把 SFT 单轨迹样本 + DPO 轨迹对放在同一个训练轮次联合训练。
容易出现：多目标冲突，模型在拟合真值和偏好之间来回震荡；只有少数团队在做探索，工业主流是串行。
4. DPO 训练时，batch 内的配比细节
DPO 一个 batch 里面全部是轨迹对，不再混入 SFT 单真值样本（串行方案）；
batch 内部依然分层采样：维持常规 / 交互 / 难例的比例；
对难例偏好对，可以加样本权重：难例对 loss 权重上浮 1.5~3 倍，但不要过高。
5. 训练配比相关超参联动
当你提高强负样本比例：DPO 的 beta（DPO 温度系数）建议调低；beta 越小，对好坏轨迹差异惩罚越强；强负多的时候 beta 太大会导致策略崩坏。
弱负为主时：beta 可以取偏大值，偏好学习更平滑。
beta 是 DPO 最重要超参之一，智驾连续轨迹 DPO 一般 beta 在 0.1~1 区间，远小于 LLM。
四、迭代链路总结（SFT → DPO）
SFT 数据集：单条安全真值轨迹，场景分布常规为主 + 少量难例；训练得到基础规控模型，保证轨迹物理可行。
在 SFT 场景池 + 仿真场景池，批量构造 DPO 偏好对：
chosen：专家 / 优质真值；
rejected：旧模型输出、扰动轨迹、改参规划器轨迹；控制弱负为主，强负少量。
DPO 数据集场景分布：大体对齐 SFT，适度提升难例偏好对占比。
DPO 微调：低学习率，KL 约束，防止大幅度偏离 SFT 底座分布。
评估：同时看常规场景性能、长尾场景安全指标、保守度（急刹率）。
五、常见失败案例（来自工程）
rejected 全部是强负轨迹 → 模型极度保守，接管率飙升；
偏好对跨场景构建 → DPO 完全学不到偏好，指标无提升；
DPO 场景和 SFT 分布差异巨大 → 微调后基础驾驶能力退化；
只用扰动真值生成 rejected，缺少真实模型错误样本 → 仿真指标涨，实车不涨。

比如怎么生成碰撞、换道负样本、速度缩放等样本呢，有哪些规则方法

核心前提
所有下面生成的 (s, τ_chosen, τ_rejected) 必须同一个场景 s（同一帧 BEV / 图像、障碍物状态、车道完全不变），只修改轨迹；
τ_chosen：安全合规、动力学可行的基准轨迹（专家规划器 / 清洗后的人类真值 / SFT 优质输出）
τ_rejected：在同一场景下生成坏轨迹，分为三类：碰撞负样本、换道违规负样本、速度缩放负样本
生成后都要做两步校验：
动力学校验：轨迹的加速度、jerk、前轮转角在车辆物理极限内；不要生成物理不可达轨迹（DPO 会学到无效对比）
偏好校验：不能出现 “好坏搞反”；自动打分过滤歧义样本（两条轨迹分数接近就丢弃该偏好对）
一、碰撞类 rejected 轨迹生成（强负样本，控制占比≤20%）
目标：同一场景，轨迹侵入障碍物占用空间，但分两种：硬碰撞（会撞上）、近距侵入（不碰撞但安全余量不足，弱负）
建议：碰撞负样本里，70% 是近距侵入弱负，30% 真实碰撞硬负，避免模型过度保守。
方法 1：横向偏移基准轨迹（最常用）
输入：基准轨迹 τ_chosen = [(x₀,y₀,v₀), (x₁,y₁,v₁)...(x_T,y_T,v_T)]
规则：
沿着轨迹每个点的法向（垂直于前进方向）做横向偏移；
偏移方向：朝向障碍物（行人、车辆、护栏）；
偏移量按距离障碍物远近自适应：
障碍物距离 > 2m：偏移 0.6~1.2m（近距侵入，弱负）
障碍物距离 < 2m：偏移 1.2~2.0m（直接侵入障碍物 bbox，硬碰撞，强负）
平滑：偏移后对整条轨迹做 3 阶多项式平滑，保证a/jerk不超限。
例子：前方有停止车辆，基准轨迹保持 1.5m 横向余量；横向向障碍物偏移 0.9m → 横向余量只剩 0.6m（近距侵入 rejected）；偏移 1.5m → 轨迹直接压进车辆 bbox（碰撞 rejected）。
方法 2：纵向时间偏移（追尾类负样本）
适合前车跟车场景：
保持轨迹横向坐标不变；
把未来轨迹点在时间轴上往前压缩：让自车更早到达同一空间位置，等效自车速度变快；
公式思路：
基准轨迹：t=2s 到达 x=20m；
坏轨迹：t=1.2s 到达 x=20m；
结果：自车更快追上前车，TTC（碰撞时间）下降，甚至 TTC<0 触发追尾。
注意：要限制加速度上限，不能瞬间加速。
方法 3：修改规划器代价函数生成碰撞轨迹（工业首选，可控）
复用 QP 规划器（同一场景，障碍物 / 车道不变）：
基准：障碍物代价权重w_obs=10 → chosen 轨迹
生成 rejected：降低障碍物代价 w_obs=0.1~2，保持车道、平滑代价不变；规划器会生成贴近障碍物甚至侵入障碍物占用区域的轨迹。
优点：天然满足动力学约束，不需要后续额外平滑；可以批量控制碰撞类型（横向碰撞 / 追尾）。
碰撞负样本过滤规则（必加）
计算轨迹上每个时刻的距离障碍物最小距离 d_min；
若 d_min > 1.0m：不算碰撞负，丢弃；
若 d_min < 0：硬碰撞（保留少量）；
若 0 < d_min <1.0m：近距侵入弱负（主力碰撞类负样本）；
额外：TTC 阈值过滤，TTC<1.5s 标记为危险轨迹。
二、换道 / 变道违规负样本（车道越界、不合理换道，弱负为主）
分两类：① 车道压线 / 越界；② 时机错误换道（邻道有车，强行变道）
类型 A：压线 / 跨车道边界负样本
方法 A1：横向偏移基准轨迹（车道方向）
基准轨迹保持在车道中心（chosen）；
沿法向朝车道线方向偏移，偏移量：0.3~1.2m；
偏移 0.4m：轮胎压车道线（弱负）
偏移 1.0m：整车侵入邻车道（强负）
保持纵向速度不变，轨迹平滑，保证动力学可行。
方法 A2：修改 QP 车道代价权重
同一场景：
chosen：车道边界代价w_lane=8，不压线；
rejected：w_lane=0.5~2，障碍物代价不变；规划器会生成压线 / 侵入邻道轨迹。
类型 B：时机错误的强行换道负样本（交互场景，价值很高）
场景：邻道后方有来车，正常应当放弃变道；
生成规则
基准 chosen：放弃变道，留在原车道；
rejected：强制规划器输出变道轨迹，但邻道后方车辆的 TTC 很小；
实现方式：强制关闭 “邻道来车安全约束”，保留车道平滑代价；规划器输出一条几何上可行变道轨迹，但邻道车辆距离过近。
重点：这条 rejected 轨迹几何和动力学是可行的，只是交互上不安全，属于高质量弱负，DPO 最擅长学习这类偏好。
换道负样本过滤规则
计算轨迹与车道边界的最小距离；
区分：仅压线 / 完全侵入邻车道；
强行变道样本必须校验邻道车辆 TTC：TTC<2.5s 才标记为坏变道；TTC 很大的变道是合理的，不能作为 rejected；
剔除：跨实线掉头、逆行这类极端轨迹（少量保留，强负）。

六、配比、训练注意事项
负样本类型配比（DPO 数据集内所有偏好对）
速度 / 舒适性负样本：~40%（弱负主力，学习平稳驾驶）
换道 / 车道违规负样本：~40%（交互场景偏好）
碰撞侵入类负样本：~20%（其中 30% 硬碰撞，70% 近距弱负）
和 SFT 关系：
SFT 阶段只用安全可行轨迹，不会用这些扰动坏轨迹当真值；
DPO 是在 SFT 学会可行轨迹分布之后，用这组偏好对，学习 “多条可行轨迹里怎么选更好的一条”。
坑点：
不要生成物理不可行轨迹；模型会学到无意义对比；
不要一条 rejected 叠加多重缺陷；信号模糊；
强负（碰撞）比例不能太高，否则模型保守；
扰动幅度不要过大，人造痕迹太重，实车泛化差。
七、可选扩展：负样本增强的高级策略
自适应扰动幅度：根据 SFT 模型当前误差，模型容易犯错的场景，扰动幅度调小一点，生成更贴近模型错误边界的 rejected；
困难偏好对挖掘：SFT 模型在该场景预测误差大，优先在这类场景生成 DPO 偏好对；
域混合：一部分扰动生成、一部分 QP 改代价生成、一部分旧模型输出混合，避免单一来源负样本带来的分布偏移。

一、真值构造完整流水线（工业标准）
Step1：原始轨迹提取
从回放 log 里提取自车历史 + 未来轨迹：
自车定位 / IMU 输出的历史位姿序列；
把司机未来一段时间（比如未来 3s/5s，10Hz）的位姿插值，得到原始 raw 轨迹；
问题：司机操作有系统延迟 + 反应滞后 + 噪声。传感器、标定、时间不同步会造成时间戳错位。
Step2：时序对齐（必做）
传感器、定位、司机油门 / 转角信号存在时间偏移（几十～200ms）；
用时间戳补偿，把司机动作对齐到 BEV / 图像输入帧的时刻；
例子：图像帧在 t=0，司机打方向实际发生在 t=+0.15s，要回拨对齐，否则真值时序错位，模型学不准。
Step3：基础清洗过滤（过滤直接丢弃，不进真值库）
直接扔掉这类原始司机片段，不做修复，不拿来当 gt：
司机分心、低头、误操作、急打方向、无意识猛踩刹车；
采集异常：定位漂移、丢帧、点云 / 图像失效；
事故、碰撞、剐蹭片段（这类样本不做 SFT 真值，可以留着后续做 DPO 负样本）；
车辆处于接管、停机、标定模式。

打分维度：安全余量、是否压线、TTC、jerk、轨迹可行性；低于阈值不入库。
二、哪些场景必须修改 / 替换原始司机真值（重点）
原则：司机行为不符合安全 / 交通规则，或者不是最优示范，就要修正。
分成 5 大类场景：
1. 司机出现轻微不安全操作（局部修正，优先，不整体废掉整条轨迹）
特点：整体驾驶没问题，只是局部小瑕疵，不构成碰撞，但安全余量不足。
跟车距离偏近，TTC 偏低，但没有碰撞；
车辆轻微压车道线（轮胎压线，没有跨道）；
近距离紧贴护栏 / 非机动车行驶；
过弯横向余量偏小；
✅ 处理方案：局部微调轨迹
保持整体路线不变，只把轨迹往安全侧小幅偏移：拉大跟车距离、离开车道线、远离障碍物；再做平滑 + 动力学校验。
不要直接整条删掉：场景本身很宝贵（城区交互），只是司机小动作有瑕疵。
2. 司机做出明显违规、危险行为（整条轨迹替换，不用司机轨迹）
原始司机轨迹直接不能当 SFT 真值：
实线变道；
无保护左转抢行，对向有来车；
路口抢黄灯、超速通过；
近距离切入大货车；
高速近距离连续变道；
✅ 处理方案：抛弃司机轨迹，调用专家优化规划器，在完全相同的场景（障碍物、车道、交通灯不变）重新生成一条合规安全参考轨迹作为真值。
场景保留，只是真值换掉。这类场景大多是高价值 corner case，直接丢弃太浪费。
3. 司机保守过度（龟速，通行效率过低）
场景本身通行条件很好，但司机过度保守：
空旷路口，无障碍物，长时间低速蠕行；
高速无车，长期远低于限速行驶；
有条件安全变道，但司机一直不做合理变道，长时间压慢车流。
✅ 处理方案：替换速度剖面，保持空间轨迹不变，提升速度到合理区间；动力学校验。
原因：直接学这个真值，模型会学出过度保守，通行效率差，后续接管率高。
4. 交互场景：司机滞后 / 反应延迟（非常常见，城区重点）
典型：前方车辆减速，司机刹车踩晚了，出现紧急制动；
或者前车加速离开后，司机迟迟不恢复正常车速。
司机轨迹本身没碰撞，但属于 “补救式急刹”，不是预判式的优质驾驶。
✅ 处理方案：
保留空间路线，修正时序 / 速度曲线，提前减速，消除突发急刹，降低 jerk；
让真值变成预判型减速，而不是临危一脚刹车。
这个修正是城区真值改造最高收益的一项。原始司机很多都是滞后反应，直接学就会模型急刹多。
5. 采集 / 定位带来的轨迹失真（不是司机驾驶问题，是数据问题）
定位漂移，轨迹局部 “蛇形抖动”；
时间戳错位，导致速度剖面畸变；
弯道定位偏差，看起来压线实际没有压线。
✅ 处理：轨迹拟合平滑、时间对齐、基于车道几何修正轨迹中心线。
6. 仿真数据真值（天然需要构造，没有人类司机）
仿真场景（鬼探头、横穿行人、无保护左转）：
不存在人类回放轨迹，直接用专家规划器生成真值。
可以批量生成中性风格的参考轨迹，作为 SFT 真值。
❌ 哪些场景不要强行修改真值（保留原样）
正常合理的驾驶风格差异：有的司机习惯远跟，有的中性跟车，只要安全合规，不修改，可以作为多真值；
合理的防御性减速：路口、行人附近主动减速，这是好行为，不要改成更快速度；
临时避让合理操作：遇到突发障碍物平稳避让，轨迹安全，保留。
一句话区分：
司机行为安全、合规、预判合理 → 保留，只做基础平滑对齐；
司机行为余量不足、违规、滞后补救、极端保守 / 激进 → 局部修正 or 整条替换。
三、真值修改的两种技术实现方案
方案 A：局部轨迹优化（微调，保留司机路线）
以原始司机 xy 轨迹作为初始猜测，加约束做优化：
目标函数：贴近原始司机轨迹 + 最小 jerk
约束：
障碍物距离 > 安全阈值（比如 0.8~1m）
车道边界约束，不压线
加速度、jerk、转向角物理边界
适合：轻微瑕疵场景，尽量保留人类驾驶意图，只修复局部缺陷。
方案 B：全量专家规划重生成（完全替换 gt）

在曲率限速、启停、回正等场景表现不好，怎么构造和修改真值，使得数据增强

核心总览
曲率限速、启停、转向回正这三类问题，共性根源：
原始司机真值里，很多人过弯不提前降速、启停顿挫、回正时机五花八门；直接学 raw log，模型学到滞后动作、不合理速度曲线、方向盘回正滞后 / 超调；
属于时序耦合问题：不只是空间 xy 轨迹，核心是速度剖面 + 曲率联动 + 转向时序，单纯空间扰动增强没用；
真值改造思路：空间尽量保留驾驶意图，重点修正时序剖面、速度、加减速、jerk、曲率 - 速度绑定关系；
数据增强分两条线：
✅ SFT 侧：修正 / 重生成优质真值（作为 chosen），补齐曲率限速、启停、回正样本；
✅ DPO 侧：在同场景生成坏轨迹 rejected（过弯超速、启停急刹、回正滞后 / 过冲）做成偏好对。
原则：不要大量凭空造几何轨迹；优先基于原有真实场景，只修改速度 / 加速度 / 转向剖面，保留车道、障碍物、导航的真实环境，减少域 gap。

注意：端到端规控有两种输出范式：
A：输出轨迹 (x,y,v)（无显式转角）；
B：直接输出方向盘转角 / 前轮转角序列。
回正问题在 B 范式更突出；A 范式下回正间接体现在轨迹曲率时序：出弯后曲率平滑收敛到 0，不能曲率保持、不能来回振荡。
现象
出弯后，模型不回正 / 回正滞后 / 回正超调（S 摆动）。
根源：原始司机回正动作差异极大；很多人出弯回正时机不稳定，轨迹曲率衰减时序混乱。
1）真值改造方法
如果输出是轨迹（曲率时序版，绝大多数 BEV 规划）
原始轨迹：出弯后曲率缓慢下降、或者来回震荡。
修正思路：固定空间路径，约束曲率随弧长平滑衰减到 0
入弯：曲率逐步上升到峰值；
弯顶：维持恒定曲率；
出弯段：曲率平滑单调衰减到 0，禁止曲率二次反向（S 摆动）；
用样条拟合，增加曲率变化率约束 
dκ/ds
，禁止曲率振荡。
如果输出是转角序列（直接控制）
需要对前轮转角 δ 时序做真值修正：
入弯：δ 平滑增加；
弯内：δ 保持；
出弯：随曲率减小，单调平滑回正到 0，转角变化率受限；
人类经常出现：弯结束还保留转角、回正太快导致反向摆，这类片段需要替换转角真值。
关键点：回正不是 “出弯瞬间立刻归零”，而是随行驶距离逐步回正，和车辆动力学（阿克曼、轮胎侧偏）匹配，不能脱离车辆动力学硬改转角时序。
2）回正场景数据增强
同一弯道场景，生成多条曲率时序：
中性（主 gt）：标准平滑单调曲率衰减；
略快回正；
略慢回正（仍然稳定，无振荡）；
全部作为可行多真值，用于 SFT。
3）DPO 负样本（rejected）
同一场景，构造回正缺陷轨迹：

回正超调：曲率从正→负，轨迹 S 摆动；

五、常见踩坑点
❌ 强行把所有弯道统一降到很低速度：模型过度保守，过弯不敢正常速度行驶；要保留多风格真值，不是一刀切；
❌ 修改启停真值时，忽略前车动态：前车还没停，直接强制自车刹停；修改真值必须锁定同一帧障碍物时序；
❌ 回正真值只看时间，不看行驶弧长：车辆速度不同，回正时间应该随距离走，不是固定多少秒回方向盘；
❌ 过度平滑：抹掉合理的防御减速；例如弯道前方有行人，本身就需要更低速度，不要强行拉高速度到曲率上限；
❌ 把修正后的完美真值全部替换人类数据，完全删掉原始司机弯道样本：模型行为脱离真实人类交互。

# 初始化状态
def reset():
    a_lon_ema = 0.0
    a_lat_ema = 0.0
    j_lon_ema = 0.0
    j_lat_ema = 0.0
    return a_lon_ema, a_lat_ema, j_lon_ema, j_lat_ema

alpha = 0.181 # tau=0.5s, dt=0.1
# 舒适阈值
soft_a_lon = 1.5
hard_a_lon = 2.5
k_a_lon = 0.3

def hinge_quad(x, x_soft, x_hard, k):
    absx = abs(x)
    if absx <= x_soft:
        return 0.0
    elif absx <= x_hard:
        return k * (absx - x_soft)**2
    else:
        base = k * (x_hard - x_soft)**2
        return base + 0.5 * (absx - x_hard)

# 每一步更新
def step(a_lon_raw, a_lat_raw, j_lon_raw, j_lat_raw, state):
    a_lon_ema, a_lat_ema, j_lon_ema, j_lat_ema = state
    # EMA时间衰减平滑
    a_lon_ema = alpha * a_lon_raw + (1-alpha)*a_lon_ema
    a_lat_ema = alpha * a_lat_raw + (1-alpha)*a_lat_ema
    j_lon_ema = alpha * j_lon_raw + (1-alpha)*j_lon_ema

    # 查表获得各分项代价
    c_alon = hinge_quad(a_lon_ema, soft_a_lon, hard_a_lon, k_a_lon)
    c_alat = hinge_quad(a_lat_ema, 1.2, 2.0, 0.35)
    c_jlon = hinge_quad(j_lon_ema, 1.5, 2.5, 0.5)
    c_jlat = hinge_quad(j_lat_ema, 2.0, 3.0, 0.4)

    w_alon, w_alat, w_jlon, w_jlat = 0.2,0.25,0.4,0.3
    total_cost = w_alon*c_alon + w_alat*c_alat + w_jlon*c_jlon + w_jlat*c_jlat
    r_comfort = -total_cost
    new_state = (a_lon_ema, a_lat_ema, j_lon_ema, j_lat_ema)
    return r_comfort, new_state, total_cost

python
import numpy as np

# ========= 超参 =========
dt = 0.1
tau_smooth = 0.3    # 信号平滑时间常数
tau_decay = 0.5     # cost的时间衰减常数
alpha = 1 - np.exp(-dt / tau_smooth)

# 分项权重
w_alon, w_alat, w_jlon, w_jlat = 0.2, 0.25, 0.4, 0.3

# 四段代价函数
def cost_alon(x):
    x_soft, x_hard, k1, k2 = 1.5, 2.5, 0.3, 0.8
    absx = abs(x)
    if absx <= x_soft:
        return 0.0
    elif absx <= x_hard:
        return k1 * (absx - x_soft)**2
    else:
        base = k1 * (x_hard - x_soft)**2
        return base + k2 * (absx - x_hard)

def cost_alat(x):
    x_soft, x_hard, k1, k2 = 1.2, 2.0, 0.35, 0.9
    absx = abs(x)
    if absx <= x_soft:
        return 0.0
    elif absx <= x_hard:
        return k1 * (absx - x_soft)**2
    else:
        base = k1 * (x_hard - x_soft)**2
        return base + k2 * (absx - x_hard)

def cost_jlon(x):
    x_soft, x_hard, k1, k2 = 1.5, 2.5, 0.5, 1.2
    absx = abs(x)
    if absx <= x_soft:
        return 0.0
    elif absx <= x_hard:
        return k1 * (absx - x_soft)**2
    else:
        base = k1 * (x_hard - x_soft)**2
        return base + k2 * (absx - x_hard)

def cost_jlat(x):
    x_soft, x_hard, k1, k2 = 2.0, 3.0, 0.4, 1.0
    absx = abs(x)
    if absx <= x_soft:
        return 0.0
    elif absx <= x_hard:
        return k1 * (absx - x_soft)**2
    else:
        base = k1 * (x_hard - x_soft)**2
        return base + k2 * (absx - x_hard)

def calc_total_comfort_cost(traj):
    """
    traj: array(N,4) [a_lon, a_lat, j_lon, j_lat]
    return: total comfort cost
    """
    N = traj.shape[0]
    # 初始化EMA状态
    a_lon_filt = 0.0
    a_lat_filt = 0.0
    j_lon_filt = 0.0
    j_lat_filt = 0.0
    total_cost = 0.0
    for i in range(N):
        alon_raw, alat_raw, jlon_raw, jlat_raw = traj[i]
        # Step1 EMA平滑acc/jerk
        a_lon_filt = alpha * alon_raw + (1-alpha)*a_lon_filt
        a_lat_filt = alpha * alat_raw + (1-alpha)*a_lat_filt
        j_lon_filt = alpha * jlon_raw + (1-alpha)*j_lon_filt
        j_lat_filt = alpha * jlat_raw + (1-alpha)*j_lat_filt

        # Step2 查表获得单点分项cost
        c_alon = cost_alon(a_lon_filt)
        c_alat = cost_alat(a_lat_filt)
        c_jlon = cost_jlon(j_lon_filt)
        c_jlat = cost_jlat(j_lat_filt)
        ci = w_alon*c_alon + w_alat*c_alat + w_jlon*c_jlon + w_jlat*c_jlat

        # Step3 时间衰减权重
        tau_i = i * dt
        lam = np.exp(-tau_i / tau_decay)
        total_cost += ci * lam
    return total_cost
